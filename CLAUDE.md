# Claude Code Instructions

## VolleyStats - Volleyball Statistics Management

**Tech Stack**: Next.js 15 + React 18 + TypeScript + Supabase + RxDB (offline live match)

**Key Characteristics**:
- Live match tracking works offline (RxDB + Supabase sync); other screens use live Supabase data
- Real-time match tracking (core feature)
- PWA with service worker
- Repository pattern for data access (lib/api/)
- Command pattern for undo/redo (lib/commands/)

## Database Schema Quick Reference

**13 Tables** (all except `profiles` have `created_at`, `updated_at` and a `_deleted` soft-delete flag; all IDs are UUID strings):

**Core Entities**:
- `profiles` - User profile (name, language, favorite club/team)
- `clubs` - Volleyball organizations
- `club_members` - Membership with roles (owner/admin/member)
- `teams` - Teams (→ clubs, championships)
- `team_members` - Players/staff (→ teams)
- `championships` - Competition categories (→ seasons)
- `seasons` - Competition seasons
- `match_formats` - Match rules (2x2, 3x3, 4x4, 6x6)

**Match Data**:
- `matches` - Match records (→ teams, match_formats, championships, seasons)
- `sets` - Individual sets (→ matches)
- `score_points` - Point-by-point (→ sets)
- `player_stats` - Individual stats (→ sets, team_members)
- `events` - Match events and comments, including substitutions (`event_type` 'substitution') (→ matches, sets)

**Key Relationships**:
- clubs (1) ←→ (N) teams
- teams (1) ←→ (N) matches (home/away)
- matches (1) ←→ (N) sets, events
- sets (1) ←→ (N) score_points, player_stats

*Columns: [lib/supabase/database.types.ts](lib/supabase/database.types.ts) (generated by `npm run supabase:types`). Table meanings and RLS: [.claude/docs/05-database-schema.md](.claude/docs/05-database-schema.md)*

## Development Guidelines

### Essential Patterns
1. **Data Access**: Screens other than the live match read and write live data through the API layer via hooks (e.g., `useTeamApi()`), which call Supabase directly.
2. **Offline live match**: Live match tracking must work offline, so it writes to RxDB (`useLocalDb` + `lib/commands`) and `SyncManager` replicates to Supabase. Keep local data scoped to what a match needs (`syncMatch(matchId)` pulls one match on demand) rather than syncing whole tables, because the app shouldn't load all data onto the device.
3. **Error Handling**: Try-catch with toast notifications
4. **Type Safety**: Use types from [lib/types.ts](lib/types.ts)
